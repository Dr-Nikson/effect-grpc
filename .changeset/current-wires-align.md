Move to Connect-RPC 2.3, protobuf-es 2.17 and buf 1.75 (#65)

**Breaking.** Node.js 20 is no longer supported, because the `engines` field of `@connectrpc/connect-node` 2.3 says `>=22`. On Node.js 20, npm warns with `EBADENGINE` and pnpm prints no engine warning. The engines check fails an install only when `engine-strict` is set. The peer range of `@connectrpc/connect` is now `^2.3.0` (it was `^2.1.0`), and the peer range of `@bufbuild/protobuf` is now `^2.17.0` (it was `^2.8.0`). Use `@bufbuild/protoc-gen-es` 2.17 or later next to them. protoc-gen-es 2.17 declares an exact `@bufbuild/protobuf` 2.17.0 peer, so upgrade the two together and run `buf generate` again.

`@connectrpc/connect-node` 2.3 pins its `@connectrpc/connect` peer to 2.3.0, and `@bufbuild/protoplugin` 2.17 pins its `@bufbuild/protobuf` dependency to 2.17.0. With `@connectrpc/connect` 2.3.0 and `@bufbuild/protobuf` 2.17.0, an install holds one copy of each. If your app installs an older version of either package, npm fails by default with `ERESOLVE`. pnpm warns about an unmet peer, or fails with `ERR_PNPM_PEER_DEP_ISSUES` when `strict-peer-dependencies` is on. Neither npm nor pnpm installs a second `@connectrpc/connect`. An install that completes with an older `@bufbuild/protobuf` holds a second copy, the 2.17.0 that protoplugin pins. A call through effect-grpc loads your app's copy, not that one.

What else changes for a user:

- A connection attempt that takes longer than 20 seconds now fails the call with a `GrpcException` of `Code.Unavailable`, so `Effect.catch` catches it. Set `connectTimeoutMs` in the `pingOptions` of the client config to change the limit. The limit covers TCP and TLS setup. A plain-text HTTP/2 (h2c) server that accepts the TCP connection and then sends nothing still leaves the call pending, even with `connectTimeoutMs` set. `defaultTimeoutMs` and `Effect.timeout` still end such a call. With `defaultTimeoutMs: 30000` and a connection attempt that stalls, the call now ends at 20 seconds with `Unavailable`. Before, it ended at 30 seconds with `DeadlineExceeded`.
- A client call now fails at once with a `GrpcException` of `Code.Internal` when the server closes the HTTP/2 stream with `NO_ERROR` before it responds. With Connect 2.1, such a call stayed pending until a timeout ended it.
- A call now fails with `Code.Internal` when a proto3 string field, or an editions string field that keeps the default `utf8_validation`, holds invalid UTF-8. Before, the bytes decoded to replacement characters. This holds when the body is protobuf, over gRPC, gRPC-web and Connect. It also holds for a response that the effect-grpc client reads, and the client's call then fails with a `GrpcException`. Invalid bytes in a proto2 string field, in an editions field with `utf8_validation = NONE`, and in a Connect JSON body still decode to replacement characters.
- A JSON request with a duplicate key now fails with `Code.InvalidArgument`, where the last value won before.
- A binary tag written in six or ten bytes, or in five bytes with bit 32 set, is now rejected, and the call fails with `Code.Internal`. Before, the parser accepted it.
- protobuf-es now limits a message to 100 levels of nesting, where 2.8 set no limit. A message that nests deeper fails with `Code.Internal` over gRPC, gRPC-web and Connect when the body is protobuf, and with `Code.InvalidArgument` over Connect JSON. A `google.protobuf.Struct` field fails sooner, at 50 nested objects over binary and at 99 over JSON. The effect-grpc client applies the limit to a response too, and the call fails with a `GrpcException` of `Code.Internal`. Raise the client's limit with `binaryOptions.recursionLimit` in the client config. An effect-grpc server has no option to raise it.
- A string that starts with U+FEFF now keeps that character over gRPC, gRPC-web and Connect when the body is protobuf, and in a response that the effect-grpc client reads. protobuf-es 2.8 dropped it. Connect JSON is unchanged.
- A proto3 `double` field that holds `-0.0` is now written, in binary and in JSON. protobuf-es 2.8 left it out.
- JSON output and input changed in a few places. An enum value with aliases is written under its first name. An `Any` that holds a well-known type without its own JSON form, such as `Empty` or `SourceContext`, now writes that type's fields next to `@type` instead of under `value`, and the old form no longer parses. `toJson` throws for a `Timestamp` with `nanos` above 999999999, for a `Duration` whose `nanos` and `seconds` differ in sign, and for a `FieldMask` path such as `a_1` whose camelCase form does not convert back to it. An open enum number outside the int32 range is rejected when JSON is parsed.
- A regenerated `_pb.ts` types a message-typed field as `user?: User | undefined`, where it was `user?: User`. With `exactOptionalPropertyTypes` on, you can now assign `undefined` to such a field.
