Fail generated client calls with `GrpcException` instead of defects, and send a handler's JSON data to the client (#27, #12, #72)

**Breaking.** Each generated client method, and each method of `EffectGrpcClient.ClientExecutor`, now fails with `GrpcException`. Its type was `Effect.Effect<Response>`, and every failed call died with Connect's `ConnectError` as a defect. A status that the server sent, a transport failure such as a closed port (`Unavailable`) and a passed deadline (`DeadlineExceeded`) now reach the error channel, where `Effect.catch`, `Effect.catchTag`, `Effect.retry` and the other error operators see them. Code that recovered these defects with `Effect.catchDefect`, `Effect.sandbox` or `Cause.findDefect` stops seeing them. The exception's `cause` holds the `ConnectError`. Code that read the failure as a `ConnectError` still compiles but gets other answers. `error instanceof ConnectError` is false, `ConnectError.from(error).code` is `Code.Unknown` instead of the call's code, and `String(error)` gives `[5] User not found` where it gave `ConnectError: [not_found] User not found`. The status message and `exception.message` of a failed call's client span lose Connect's code prefix, such as `[not_found]`. An interrupted call still ends interrupted, not failed.

**Breaking.** Run `buf generate` again. Code that an earlier `protoc-gen-effect` generated types its calls as never failing, while the calls now fail with `GrpcException`.

**Breaking.** A server now passes a downstream call's failure on to its own caller. When a handler or a context transformer yields a call of a generated client and does not map its error, the server sends that call's code, message and data. Before, it sent `INTERNAL` with the message `Internal server error`. For a closed downstream port, the message is `connect ECONNREFUSED <ip>:<port>`, so the caller learns the downstream's internal address. Such code compiles unchanged, because the call, the handler and the context transformer all fail with `GrpcException`. To keep such a failure on the server, map it to your own `GrpcException` with `Effect.mapError`. `Effect.orDie` keeps it there too, and the server sends `INTERNAL` with `Internal server error`, unless a second defect, such as a dying finalizer, follows. In that case the server still sends the call's code, message and data.

`GrpcException` has a new field, `data`, an `Option` of JSON (`Schema.Json`). `GrpcException.withData(error, data)` sets it, and it also works in a pipe. The server sends the data as one `google.protobuf.Value` in the standard gRPC status details: in the `grpc-status-details-bin` trailer over gRPC and gRPC-web, and in the error body over Connect. `GrpcException.from` reads the data back from a `ConnectError`, so the generated client's failure carries the code, the message and the data. `buf curl` prints the data under `details[].debug` on all three protocols, and so does the JSON error body of a Connect call. `new GrpcException({...})` takes `data` as an optional field that defaults to `Option.none()`, so code that builds the class keeps compiling.

Known limitations:

- A reader gets the data as `JSON.stringify` writes it. `NaN` and `Infinity` arrive as `null`. The server does not send data that `JSON.stringify` refuses, such as a cycle, or data nested about 100 or more levels deep. The status then goes out without it. `GrpcException.from`, and so the generated client, reads data nested about 50 or more levels deep as `Option.none()`, even with a higher `binaryOptions.recursionLimit` in the client config.
- Over gRPC the details travel in a trailer, so a status past HTTP/2's header limit fails the call with `INTERNAL`. In a test with Connect 2.3, 32 KiB of data passed and 63 KiB failed. After such a status the server closes the connection, and a call that the same client starts right after the failed one also fails with `INTERNAL`.
- The generated client still speaks gRPC only. A Connect client in Node on gRPC-web or Connect reads the same `GrpcException`, data included, with `GrpcException.from(Code.Unknown, error)`.
